# SFX Notes

This project currently uses a free, publishable SFX path:

- DeadSounds reference recordings in `free/deadsounds/`
- Post-processed weapon layers in `enhanced/`
- AudioFly generated WAV samples in `generated/`
- CC0 Kenney audio samples in `curated/`
- Local-only test overrides in `local-reference/`
- Browser WebAudio synthesis in `src/audio.js` for lightweight UI and fallback layers

The weapon layer now resolves in this order:

1. `local-reference/manifest.json` for private local tests.
2. Real/reference recordings in `free/deadsounds/` for the most exposed fire sounds.
3. Post-processed `enhanced/` WAVs for longer tails, low-frequency body, and battlefield reflections.
4. AudioFly `generated/` WAVs as fallback.
5. WebAudio synthesis for UI and compact fallback cues.

The enhanced layer is generated by `scripts/generate_enhanced_sfx.py`.

The AudioFly layer remains available as a fallback source for weapon fire and impact sounds:

- Infantry: close assault rifle burst
- Armor: main battle tank cannon
- Helicopter: rotor and rocket attack run
- Artillery: self-propelled howitzer shot
- Rocket artillery: MLRS salvo
- Heavy and mobile air defense: SAM launch / short-range AA burst
- Drone: UAV strike
- Fighter and bomber: jet strike / heavy bomb run
- Impacts: heavy ground explosion, armor-piercing hit, airburst

The WebAudio layer still gives UI, lock-on, deploy, electronic warfare, smoke, repair, and fallback events a different sound identity:

- Infantry: short rifle bursts, radio clicks, gear movement
- Armor: heavy cannon transient, metal impact, low recoil thump
- Helicopter: rotor bed plus burst fire
- Artillery: hydraulic setup, cannon fire, delayed impact
- Rocket artillery and missiles: rising launch sweeps, salvo rhythm, heavy blast
- Heavy and mobile air defense: radar pings, missile launch, interception crack
- Drone: small engine layer, target lock, compact strike
- Fighter and bomber: jet pass, lock tone, delayed explosions
- Electronic warfare and smoke: radio static, glitch sweep, low filtered noise

## Open-source AI sound generation check

AudioFly is wired into the game pipeline through `scripts/audiofly_generate_sfx.py` and `assets/audio/sfx/audiofly-prompts.json`. The local model checkout lives under `output/AudioFly-inspect`, and the generated files are normalized into `assets/audio/sfx/generated`.

ThinkSound and FishAudio-related projects are still useful for experiments, but they are not wired into the game pipeline right now:

- Alibaba/FunAudioLLM ThinkSound is open source, but its README states code, model and dataset are for research and educational purposes; commercial use requires contacting the authors.
- Fish Speech is released under a research license.
- Fish Diffusion code is MIT, but it is a TTS / SVS / SVC training framework rather than a direct game sound-effect generator; its terms also require users to handle dataset authorization, attribution, and AI-generated disclosure.

For this game, use AudioFly / CC0 samples as the default free route, and treat the WebAudio layer as support rather than the main weapon-impact sound.

## Local reference overrides

`src/audio.js` loads `local-reference/manifest.json` at startup. If an event is present there, the local file is played first; if it fails, the game falls back to the generated/curated sound.

Use this only for local experiments with material you have rights to test. The folder is ignored by git except for the README and example manifest.
